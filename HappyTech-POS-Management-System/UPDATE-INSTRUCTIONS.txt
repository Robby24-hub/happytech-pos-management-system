Happy Tech Store — Inventory, Refund Approvals & Notifications Update

INSTALLATION
1. Back up your project first.
2. Extract this ZIP into your existing project root (the folder containing package.json).
3. Allow the included src files to overwrite their matching files. Keep all other files.
   Do NOT delete src. This ZIP contains only changed/new files.
4. Run npm run dev. No new packages or npm install are needed.

CHANGES
- Product groups store their own default unit.
- Settings provides a default low-stock threshold for every group using that unit.
- Product creation includes group, image, name, retail stock, selling price, editable retail threshold, POS availability, and optional wholesale sizes with separate prices and thresholds.
- Wholesale stock is one shared pool in the group's base unit. Selling a 25 kg pack subtracts 25 kg from wholesale stock. Wholesale thresholds count complete packs and default to the group threshold divided by pack size, rounded up. All thresholds remain editable.
- POS uses the configured units, sizes, prices, and stock pools.
- Refunds require an active owner/admin PIN plus a reason. Other reason requires an explanation.
- Successful refunds do not increase stock. A yellow approval section appears above the Inventory table. Owners/admins can approve or reject; approval restores the original retail/wholesale pool once. Reject leaves stock unchanged.
- Products awaiting a return decision cannot be deleted until the decision is made. Group reassignment requires matching units to avoid changing the meaning of stored stock.
- Notifications open the relevant page, support marking as read/removal, and persist those choices. The unread badge displays a maximum of 99+.
- Yellow alerts, orange warnings, and red danger states.

EXISTING DATA
Existing saved products, groups, accounts, sales, and settings are preserved. Missing unit/threshold fields are filled automatically. Previously processed refunds are not retroactively queued because their stock was already handled by the earlier version.

VALIDATION
Production build passed. Browser checks covered group creation, settings defaults, product overrides, wholesale sale pricing/stock deduction, refund reason validation, wrong PIN rejection, pending stock, approval/rejection, notification navigation/persistence, 99+ count, and desktop/mobile product modal layout.
